# 这一杯 · 小方

为 Decaid 皮肤「这一杯」提供 CRYSTAL 小方蓝牙连接与控制。此驱动移植自本项目已经开发的经典版 de1app 小方控制器 `core.tcl`、`recipes.tcl` 和 `plugin.tcl`，独立实现，不依赖其他作者的小方插件。

版本：0.1.6。目标运行环境：Decaid 0.9.0+2977，提交 `b9f9d0559106809a70dea2023f6bce34b5bdd3ca`。蓝牙连接由 Decaid 持有；皮肤只调用本插件接口。

启动研磨前，设定刀距和设备读回的目标、实际刀距均须达到 10 µm。低于阈值时页面提示“刀距过近，拒绝启动”。

## 安装

1. 把 `thiscup-crystal.reaplugin-0.1.6.zip` 放入平板下载目录。
2. Decaid → 设置 → 插件 → 右上角插件操作 → 安装插件 → ZIP 文件，选择安装包。
3. 启用「This Cup · 小方」。开启小方电源，退出占用小方的其他应用，再从皮肤的小方窗口连接。

插件使用 `events.workflow` 权限，用于接收 Decaid 提供的当前工作流。更新皮肤与插件后须重载插件，使权限和首次工作流事件生效；尚未收到服务端快照时，开始／应用会被拒绝，停止仍可用。

不要同时启用另一个匹配 CRYSTAL 的蓝牙驱动，Decaid 会将两个匹配项判为冲突。插件未安装或小方未连接不影响咖啡机与秤的功能。

## 操作

- 打开窗口及连接：只读取设备，不调距、不修改转速、不启动。
- 应用：写入并读回刀盘、进豆转速，再调距，确认结束并连续稳定 1.5 秒。不会启动磨豆。
- 开始：先完成同一套应用流程，确认机器空闲且间距未变化，再发送所选手动、定时或智能启动指令。
- 停止：取消尚未完成的调距或待启动流程，再发送停止。停止会使此前读到的操作版本失效；网络中迟到的旧应用／启动也会被插件拒绝。重新读取状态后的新一次明确操作仍可用。
- 保存到当前方案：皮肤将配方按设备 ID 与曲线 ID 独立保存在 Decaid 的共享键值存储，不控制磨豆机。不同曲线并发保存不覆盖彼此；同一设备的同一曲线仍按最后写入结果保存。旧集合只读兼容，不按名称猜测迁移。保存结果显示实际目标曲线名称。

重启后，目标间距或两项转速为零时视为参数待确认；即使实际位置仍保留 220，也不把这些零值填成方案或显示为可信设备参数。本曲线的有效方案、用户已编辑草稿会保留；有保存来源的上次有效设置显示为“上次设置 · 设备待确认”。没有有效来源的参数留空，用户可填写或借用方案后明确应用，读取和连接不会自动写入默认值。

## 多台磨豆机

- 设备用 Decaid 原生设备 ID 区分，不用蓝牙名称猜测。可为每台设置 1–24 字的名称。名称不能与其他已知设备当前显示名重复（有别名时比较别名，否则比较原名）；忽略英文大小写，去除首尾空白并合并连续空白。保留本机原名合法，已记住但离线的设备也参与检查。
- 上次选定设备和名称保存在平板插件存储。平板与局域网网页共用这份选择，重新打开会沿用。首次只有一台已连接设备时可自动选定；发现多台且没有默认设备时需要选择。
- 已保存的默认设备离线时保留选择，不自动换另一台。已绑定且可发现的目标直接连接，首次绑定或目标不可用时重新扫描；扫描使用 `GET /devices/scan?connect=false`，不会主动连接全部设备。
- 选择设备只改变插件的控制目标，不应用参数、不启动。连接所选设备时，Decaid 原生磨豆机控制器会先断开之前连接的磨豆机，再连接新设备；当前接入方式不能保持两台磨豆机同时在线。运行、调距、读参或已连接但状态未确认时拒绝切换。原生连接未成功或读回身份改变时显示失败。
- 每台设备分别保存草稿与曲线研磨方案。旧版本没有设备身份的配置不会自动分配给任何机器；旧研磨方案在列表中标为未关联，允许用户明确借用后保存到当前设备。
- 新设备上电读到全零时仍显示参数待确认，绝不继承另一台的设置或自动发送默认参数。

## 确认规则

设备通讯串行执行，每次写入等待蓝牙确认。调距必须观察到忙碌再回到空闲，实际间距与目标相差小于 3 μm，并连续稳定 1.5 秒；仅有「指令已发出」或某次读数等于目标都不算完成。

单次回应超时会结束当前操作，但不会让下一条蓝牙请求超越仍未返回的请求。连接中断、通知数据损坏和用户停止都会取消后续动作；不自动重放操作。硬件停机未确认时会明确报错，仍可使用小方实体停止键。

## 皮肤接口

地址均相对于 `http://平板地址:8080/api/v1`。

- `GET /plugins/thiscup-crystal.reaplugin/ui?state=1`：读取选定设备 `deviceId/deviceName/deviceAlias`、设备列表、`multiDevice/preferencesReady`、连接、实际值、草稿、活动操作、最近操作结果及 `commandFence: {instanceId, revision}`，不访问硬件。
- `POST /plugins/thiscup-crystal.reaplugin/ui`：JSON 请求 `{ "commandId": "apply", "params": { "deviceId": "从设备列表取得的选定设备ID", "commandFence": { "instanceId": "从状态读取", "revision": 2 }, "expectedWorkflow": { "id": "打开面板时的工作流ID", "profile": { "title": "完整曲线内容示例" } }, "config": { "grindSize": 200, "motorRpm": 900, "feedRpm": 20, "bootMode": "smart" } } }`。
- `selectDevice` 接收 `deviceId`，仅保存默认选择；`renameDevice` 接收 `deviceId/name`，仅保存显示名称。配置加载完成之前拒绝修改。
- 其他命令都必须带当前 `deviceId`；与服务器当前选择不同即拒绝。切换设备还会使此前的操作版本失效，切回同一台也不能重放旧请求。
- 支持 `readAll`、`apply`、`start`、`stop`；后三个长操作返回 `{ "ok": true, "result": { "operationId": "…", "status": "accepted" } }`。`readAll` 也返回操作凭据。
- `apply`／`start` 必须携带用户点击当刻已读到的 `commandFence`。随后的就绪检查不能刷新这次操作的版本。缺失或失效时返回 `code: "cancelled"`，不写入蓝牙；停止、操作接纳、断连和重新连接都会使旧版本失效，驱动重建还会更换 `instanceId`。`stop` 不需要版本，但必须明确指定当前设备 ID。皮肤和插件须一同更新；旧客户端缺失版本时不能继续启用开始／应用。
- `apply`／`start` 还必须携带打开面板时冻结的 `expectedWorkflow: {id, profile}`，其中 `profile` 为完整内容。插件只从 Decaid 的 `workflowUpdated` 事件建立当前真值，不以客户端请求初始化真值；未收到初始事件、工作流 ID 或曲线内容不一致时拒绝。后续工作流变化会使旧 HTTP 请求版本失效并取消尚未发出的应用／启动动作，但不取消停止或只读连接流程。
- 服务端事件不包含方案库 ProfileRecord ID，此处校验的是工作流 ID 与曲线内容。已经交给原生蓝牙层的在途写入不能被之后的事件原子撤回；真正开始研磨后更换曲线也不会被当作已经停止，停止仍需明确执行。
- `accepted` 只表示接收。轮询 GET 的 `operations`，找到同一 `id` 后以 `done`、`error`、`cancelled` 判定结果。启动操作的 `done` 表示启动流程已确认，不代表整次研磨结束；研磨结束需观察实际 `state`。
- `setConfig` 只保存草稿；`getConfig`、`getValues` 只读缓存。
- 通用设备连接仍使用 Decaid 原生 `PUT /devices/connect`，设备编号由发现列表取得，不能拼造。

皮肤完整方案的间距 1–1500 μm、刀盘转速 1–1500 rpm、进豆转速 1–150 rpm，均为整数；零值占位不会通过应用、开始或方案保存校验。模式为 `manual`、`timed`、`smart`。

曲线方案使用 `/store/thiscup-crystal-recipes/d-<设备ID编码>--p-<曲线ID编码>` 的单键写入和读回，列表读取该命名空间 `?full=1`；新记录为 `schemaVersion:4`，含 `deviceId/profileId/title/config`。旧 schema 2/3 与 `/store/thiscup/crystalRecipes` 只读，均不会自动关联设备。该存储接口不支持条件写入，同一设备同一曲线的跨端保存按最后写入结果生效。

原生 Decaid 的通用磨豆机控件也可调用启动、停止、间距和刀盘转速。受原生调用时限限制，长操作同样在后台执行；皮肤使用上述操作凭据核对完成状态。原生控件本身的返回不能当作硬件完成证据。

## 验证

本地驱动测试：`node --test tests/driver.test.mjs`。皮肤适配器测试：从皮肤目录执行 `node --test 验证/grinder.test.mjs 验证/grinder-devices.test.mjs`。

模拟测试覆盖严格数据解码、串行写入、读回、忙碌到空闲、稳定等待、取消待启动、停止、迟到回应、断连、重复连接及配置持久化。另覆盖重启零值保留来源草稿、服务端初始工作流未知、跨端切换后旧请求抵达、调距等待中换工作流，以及曲线事件不得取消排队停止。真实设备的安装、调距和短时启停由主开发线程单独验证，模拟通过不代表实机已经通过。

双设备模拟测试覆盖默认选择和名称持久化、离线目标不替换、两台连接不串控、切换使旧请求失效、忙碌拒绝切换、每台草稿与曲线方案隔离、旧方案仅显式借用。
